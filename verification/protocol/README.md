# 微積分演算における観測形式

この文書では、観測バッチの書き方と、Lean の検査器が演算族ごとに再計算して確かめる条件を確認できます。

観測バッチに収めた入力と観測値は、検査器が検査するまでは未検証の値です。判定は観測バッチには含まれず、検査器が検査結果にだけ記録します。

## 共通規約

観測バッチは、形式識別子と観測一覧を項目に持つ、正規 JSON のオブジェクトです。

- 形式識別子: `schema`
- 観測一覧: `cases`

観測バッチの JSON Schema は `schema/calculus-observation-batch.schema.json` にあり、形式識別子には `neco.calculus.observation-batch.v1` を使います。

観測一覧の各観測の項目は、観測識別子、演算族、入力、観測値です。

- 観測識別子: `caseId`
- 演算族: `operation`
- 入力: `input`
- 観測値: `observation`

観測識別子は、バッチの中で空でなく、一意である必要があります。

**成功観測と失敗観測**

観測値は、値を持つ成功観測か、型付きの失敗を持つ失敗観測のどちらかです。Lean の検査器は、成功観測では入力から値を再計算して観測値と照合し、演算族ごとの条件が成り立つかを確かめます。失敗観測では、入力について演算族ごとの条件を判定し、その判定の結果が、記録された失敗の種別と整合するかを確かめます。

**正規 JSON の符号化**

- 文書: UTF-8 で符号化したオブジェクト
- 項目名の順序: Unicode の符号位置の順
- トークン間の空白文字: なし
- 復号: 重複した項目名を拒否する
- 再符号化: 再符号化したバイト列が入力のバイト列と一致する
- ダイジェスト: 確定したバイト列に対する SHA-256

**値の表し方**

- 整数: 正規の十進文字列
- 二進有理数 ( dyadic rational ): 整数と指数の組
- 区間: 下端と上端の二進有理数
- 有理係数: 分子と正の分母

## 初版の演算族

初版の形式は 10 種類の演算族を扱います。以下の各節では、演算族ごとに、入力、成功観測、失敗観測と、Lean の検査器が確かめる条件を示します。各節の見出しの括弧内は、その演算族を指定する `operation` の値です。

多項式の係数列は、昇冪の順に並べた整数の列です。正規の係数列は、空でない列のうち、長さが 1 であるか末尾の係数が非零であるものです。

### 多項式の厳密評価 ( `polynomial-exact` )

- 入力: 係数列と点
- 成功観測: 値
- 失敗観測: 空の係数列
- Lean の再計算:
  - 係数列が正規であること
  - 観測値が、点における多項式の値と等しいこと

### 多項式の包含区間 ( `polynomial-enclosure` )

- 入力: 係数列、下端、上端、精度
- 成功観測: 下端と上端
- 失敗観測: 精度の上限超過
- Lean の再計算:
  - 係数列が正規であること
  - 入力区間と出力区間で、下端が上端以下であること
  - 出力区間が、Lean の区間演算で求めた多項式の区間を含むこと

### 有理関数の厳密評価 ( `rational-exact` )

- 入力: 分子、分母、点
- 成功観測: 値
- 失敗観測: 定義域外
- Lean の再計算:
  - 分子と分母の係数列が正規であること
  - 点における分母の値が非零であること
  - 観測値が、点における分子と分母の値の商と等しいこと

### 有理関数の区間評価 ( `rational-interval` )

- 入力: 分子、分母、下端、上端、精度
- 成功観測: 下端と上端
- 失敗観測: 分母の区間が零を含む
- Lean の再計算:
  - 分子と分母の係数列が正規であること
  - 入力区間と出力区間で、下端が上端以下であること
  - Lean の区間演算で求めた分母の区間が零を含まないこと
  - 出力区間が、Lean の区間演算で求めた商の区間を含むこと

### 符号変化区間 ( `root-bracket` )

- 入力: 係数列、下端、上端
- 成功観測: 符号変化の検証結果
- 失敗観測: 符号変化なし
- Lean の再計算:
  - 係数列が正規であること
  - 下端が上端より小さいこと
  - 両端における多項式の値の符号が異なること
  - 検証結果の種類が符号変化 ( `sign-change` ) であること

### 二分法 ( `bisection` )

- 入力: 係数列、下端、上端、要求反復数
- 成功観測: 手法、収束状態 ( `refined` または `exact-dyadic-root` ) 、最終区間、実行反復数、各反復の記録
- 失敗観測: 反復数の上限超過
- Lean の再計算:
  - 係数列が正規であること
  - 要求反復数が 1 以上 19 以下であること
  - 初期区間の下端が上端より小さく、両端の値の符号が異なること
  - 手法が二分法 ( `bisection` ) であること
  - 各反復の中点、中点の符号、選んだ半区間が、再計算の結果と一致すること
  - 最終区間、収束状態、実行反復数が、再計算の結果と一致すること

### 偶数重複度の接触 ( `even-touch` )

候補点が多項式の偶数重複度の根であり、多項式が符号を変えずに零に接することを観測します。

- 入力: 係数列、候補点、微分階数の上限
- 成功観測: 重複度
- 失敗観測: 偶数重複度の接触なし
- Lean の再計算:
  - 係数列が正規であること
  - 候補点で最初に非零となる導関数の階数が、重複度と等しいこと
  - 重複度が 2 以上の偶数で、微分階数の上限以下であること

### 局所領域の遷移 ( `local-region-transition` )

候補点を含む区間で、多項式が候補点にある零点を境に符号を変えることを観測します。観測値の零点の記録 ( locus ) は、候補点の番号、種類、重複度から成ります。

- 入力: 係数列、候補点、下端、上端、微分階数の上限、精度
- 成功観測: 零点の記録の列、その件数、区間上の多項式の符号の判定
- 失敗観測: 候補点が区間に含まれない
- Lean の再計算:
  - 係数列が正規であること
  - 候補点が下端より大きく、上端より小さいこと
  - 両端における多項式の値の符号が異なること
  - 候補点で最初に非零となる導関数の階数が重複度と等しく、重複度が微分階数の上限以下の奇数であること
  - 零点の記録の件数と列の長さがともに 1 であること
  - 零点の記録の種類が遷移 ( `transition` ) で、候補点の番号が 0 であること
  - 符号の判定が、区間内で符号が変わることを表す `varies` であること

### 曲面の厳密評価 ( `surface-exact` )

有理パラメータ曲面を、パラメータ u, v の点で評価します。座標多項式は x, y, z の座標を表す u, v の有理係数の多項式で、分母は三座標に共通の u, v の多項式です。

- 入力: 分母、パラメータ、座標多項式
- 成功観測: 三座標の値
- 失敗観測: 定義域外
- Lean の再計算:
  - パラメータにおける分母の値が非零であること
  - 三座標の観測値が、パラメータにおける座標多項式の値を分母の値で割った商と等しいこと

### 曲面の検証付き評価 ( `surface-checked` )

`evaluate_surface_checked` で、有理パラメータ曲面をパラメータ u, v の区間上で評価し、三座標の包含区間を観測します。入力の来歴 ( `provenance` ) は、所有者の識別子、消費点 ( 結果を受け取る利用箇所 ) の識別子、式の識別子の列、判定の指定、要求精度、計算した実装の識別情報から成ります。判定の指定は、消費点が求める厳密な判定の種類 ( 零、等値、符号、縮退 ) と、その判定で調べる式 ( 等値の判定では二つの式 ) を表します。判定の指定は来歴の項目であり、検査器が検査結果に記録する判定 ( 「判定」の節 ) とは別のものです。

- 入力: 分母、来歴、パラメータ区間、座標多項式
- 成功観測: 来歴と三座標の区間
- 失敗観測: 分母多項式が零
- Lean の再計算:
  - 来歴の要求精度が正であること
  - パラメータ区間と三座標の出力区間で、下端が上端以下であること
  - Lean の区間演算で求めた分母の区間が零を含まないこと
  - 三座標の出力区間が、Lean の区間演算で求めた各座標の区間を含むこと
  - 出力の来歴が入力の来歴と一致すること

## 判定

検査結果は、観測ごとの判定の列か、バッチ全体に対する `invalid` の判定のどちらかです。

バイト列が正規 JSON でない場合、形式識別子か項目が形式と異なる場合、観測識別子が空か重複する場合には、検査器はバッチ全体を `invalid` と判定します。それ以外のバッチでは、観測ごとに判定を記録します。

- `verified`: 成功観測では、再計算した値が観測値と一致し、演算族の条件が成り立った。失敗観測では、記録された失敗の種別が、入力について条件を判定した結果と整合した。健全性定理により、この観測は Lean で定義した演算族の仕様を満たす
- `refuted`: 観測を復号できたが、再計算した値が観測値と異なるか、観測が条件に反した
- `invalid`: 演算族、入力、観測値のいずれかが形式に合わず、観測の復号に失敗した
- `undetermined`: 検査結果の形式に定義があり、観測器も受け付ける値。初版の検査器は、観測ごとの判定として上の三つの値だけを返す
